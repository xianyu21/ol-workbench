# Spec: 桌面端数据持久化、安全收紧与工程质量加固

Status: ready-for-agent

## Problem Statement

AxHub 原型工作台的桌面端用户把收藏、标签、最近访问、标签页布局等核心数据存在 localStorage 里，而 localStorage 挂在"端口决定的 origin"上：固定端口段被占满回退随机端口时，用户会突然发现自己的所有收藏和标签"消失"了。同时，本地服务对所有响应都带 `Access-Control-Allow-Origin: *`，渲染层又关闭了 webSecurity，任何一个网页都可以探测用户本地目录的页面清单。对维护者来说，项目没有任何测试，每次改动只能靠手工验证；扫描逻辑在服务端和前端各维护一份，页面 ID 的哈希一旦两处不一致就会直接错乱用户数据；日志无限增长、版本号双处维护、仓库里有垃圾文件和过时文档，这些都在持续增加回归风险。

## Solution

把用户核心数据（收藏/标签/最近访问/标签页/分组折叠状态）迁移为主进程磁盘持久化（userData 下的 JSON），localStorage 退化为缓存，端口漂移、清缓存、升级都不再丢数据。收紧两层安全边界：移除 webSecurity:false，本地服务不再对任意来源放行 CORS。为本地服务建立 node:test 测试（打在现有 HTTP 请求处理接缝上），并为发布配置 GitHub Actions（tag 自动构建安装包并创建 Release 草稿）。同时完成一批低风险维护项：合并双份扫描逻辑、版本号单源、日志轮转、会话恢复懒加载、iframe 内 JS 导航联动标签、更新体验改进、仓库卫生。

## User Stories

1. 作为桌面端用户，我想让收藏、标签、最近访问和打开的标签页保存在磁盘上，这样即使本地服务换了端口、清了浏览器缓存或升级了版本，我的数据也不会丢。
2. 作为桌面端用户，当固定端口段被其他应用占满、服务回退到随机端口时，我想仍能看到我的全部收藏和标签，这样我不会误以为数据丢失。
3. 作为桌面端用户，我想让历史 localStorage 里已有的收藏/标签/最近访问自动迁移到新的磁盘存储，这样升级后无需任何手工操作。
4. 作为桌面端用户，我想保留"备份导出/导入"功能并且它作用于磁盘存储，这样我可以在多台机器间迁移我的标注数据。
5. 作为安全敏感的用户，我想让本地服务不再向任意网页开放跨域读取，这样用户浏览器里打开的恶意网页无法探测我本地 AxHub 导出目录的内容。
6. 作为安全敏感的用户，我想让渲染进程在默认 webSecurity 开启的配置下运行，这样 iframe 里加载的页面不能随意跨域读取数据。
7. 作为桌面端用户，收紧安全配置后，我想让所有现有 AxHub 导出（含中文路径、iframe 嵌套、媒体资源 Range 播放）仍然正常加载，这样安全加固不以破坏功能为代价。
8. 作为维护者，我想让本地服务的行为（路径穿越防护、MIME、缓存头、Range、中文路径、API 响应）有自动化测试覆盖，这样每次改动都能立刻发现回归。
9. 作为维护者，我想让打 tag 时自动构建 NSIS/portable 安装包并创建 GitHub Release 草稿，这样发布不再依赖手工操作。
10. 作为维护者，我想让页面扫描逻辑只有一份实现，服务端和浏览器端复用同一份，这样页面 ID 哈希永远不会两处不一致而错乱用户数据。
11. 作为维护者，我想让应用版本号只有一处定义（来自打包配置），这样发版时不会出现主进程与 package.json 版本不一致。
12. 作为维护者，我想让主进程日志有大小上限并自动轮转，这样长期后台运行不会把日志写成无限大的文件。
13. 作为桌面端用户，我想让重启后恢复的多个标签页只立即加载当前激活的那个、其余在首次点击时才加载，这样冷启动不会被同时加载七八个页面拖慢。
14. 作为桌面端用户，当我在 iframe 里点击的原型页面通过 JS（location.href）跳转到另一个已收录页面时，我想让标签栏同步切换到对应标签，这样 Axure 式的页面间跳转也能被工作台追踪。
15. 作为桌面端用户，我想在下载更新时看到明确的进度提示（而不是只在窗口标题上），这样我知道更新正在进行、需要等待。
16. 作为 portable 版用户，当我手动检查更新且有新版本时，我想看到"请到 Releases 页面重新下载"的明确指引，这样我不会误以为 portable 版能自动更新。
17. 作为桌面端用户，我想让应用每隔约 24 小时自动静默检查一次更新（而不只是启动后检查一次），这样长期不关闭应用也能及时知道新版本。
18. 作为维护者，我想让仓库里不再有误生成的垃圾文件、失效的 gitignore 规则和过时的 README 描述，这样新接手的贡献者不会被误导。
19. 作为桌面端用户，所有这些改动后，我想让现有快捷键、侧栏分组、右键菜单、LRU 休眠等既有行为完全不变，这样升级没有学习成本。

## Implementation Decisions

- **磁盘持久化模块（唯一新增接缝）**：主进程新增一个最小接口的存储模块（load / save / merge），数据落在 userData 目录下的 JSON 文件；渲染层通过 preload 桥接读写，不再直接依赖 localStorage 承载核心数据。localStorage 中 `wb_axhub_*` 的历史数据在首次运行时执行一次性迁移后清退。写策略采用"变更后防抖整文件写回"，避免高频小写。
- **持久化的数据范围**：收藏、自定义标签（含颜色）、重命名、最近访问序列、标签页布局（tabs/active/tabSeq）、分组折叠状态、侧栏宽度。页面清单本身仍以磁盘目录为唯一事实来源，每次启动重新扫描合并。
- **安全收紧的前提是测试**：先建立请求层测试基线（含中文路径、Range、缓存头用例），再移除 webSecurity:false 并收紧 CORS；收紧策略为默认不发 `Access-Control-Allow-Origin`，仅对工作台 UI 资源路径按需放行。若实测发现某个 AxHub 导出依赖跨域，按"精确放行来源"处理而非整体关闭防护。
- **扫描逻辑单源**：把页面扫描（框架页过滤、编号前缀分组、djb2 页面 ID）抽成一个与宿主无关的共享实现；服务端直接 require，浏览器端由构建流程内联同一份源码。页面 ID 算法保持逐字节一致，迁移时验证新旧 ID 对已有用户数据无损。
- **版本号单源**：主进程从打包配置读取版本（app.getVersion），删除手工维护的常量；CLI 模式的服务自带版本常量保留（它独立于 Electron 发布）。
- **日志轮转**：写入前检查体积，超过阈值（约 1MB）时将当前日志改名为 .old 后重建，最多保留一份历史。
- **会话恢复懒加载**：启动恢复会话时仅激活标签立即创建 iframe，其余标签标记为待唤醒态（沿用现有休眠唤醒 UI），首次激活才建 iframe。LRU 上限逻辑不变。
- **iframe JS 导航联动**：同源前提下对 iframe 内 document 注入轻量监听（patch location 写入 + load 事件校验 pathname），命中项目清单时复用现有的 openProject 联动路径；跨域、新窗口、锚点行为维持现状不拦截。
- **更新体验**：下载进度改为页面内可见提示（复用 antd 组件，经现有 preload 桥接传进度）；portable 版在手动检查更新时返回明确的"请到 Releases 重新下载"文案；增加每 24 小时的静默定时检查，失败仍完全静默。
- **仓库卫生**：删除误生成的垃圾文件；修复 gitignore 中编码损坏的规则使其真正生效；移除已失效的"旧单文件回退"描述并同步 README/overview 与现状；构建产物目录保持忽略。
- **发布自动化**：GitHub Actions 发布工作流——推送 v* tag 时构建 NSIS + portable 产物并创建 GitHub Release 草稿（沿用现有 electron-builder 配置与发布仓库）。只出到草稿，正式发布仍由维护者确认（不自动发版）。

## Testing Decisions

- 好的测试只断言外部可观察行为：对本地服务全部通过"发起真实 HTTP 请求 → 断言状态码/响应头/响应体"验证，不 mock 内部函数；对持久化模块只通过其 load/save/merge 接口断言落盘结果与迁移行为，不窥探内部实现。
- **本地服务（现有接缝）**：临时目录构造 AxHub 标准扁平导出夹具（含中文文件名、编号前缀、框架页、resources 目录），覆盖：目录穿越防护、`/_api/tree` 结构、`/_axviewer/` 路由与 302、MIME 表、强缓存与 HTML 短缓存策略、Range 请求（含 416）、HEAD、安全收紧后的 CORS 头缺席/按需存在。服务模块已导出请求处理器，测试直接挂接，无需新增接缝。
- **持久化模块（唯一新增接缝）**：临时 userData 目录下覆盖：空启动、写入后重读一致、损坏 JSON 容错回退、localStorage 历史数据一次性迁移、页面清单合并时用户标注字段保留。
- **发布流程**：CI 工作流本身以"tag 推送后 Release 草稿出现安装包"作为验收，不写自动化测试。
- 仓库目前没有任何测试，本 spec 的服务端测试即第一份先例（Node 内置 test runner，零新增依赖，与项目零依赖定位一致）。

## Out of Scope

- macOS / Linux 构建目标（配置里声明了 dmg/AppImage 但从未验证过，本次不动，也不删除）。
- 全文检索原型内容、页面缩略图、多目录管理等新功能。
- 自动更新签名（signAndEditExecutable 维持关闭现状）。
- 旧单文件 HTTP 版（AxHub-HTTP-Server.zip）的任何维护。
- localStorage 的彻底删除（非核心数据如 UI 偏好可继续留在 localStorage）。
- 崩溃捕获/上报体系建设。

## Further Notes

- 优先级顺序（若分批实施）：持久化与迁移 → 安全收紧（先建测试基线）→ 测试与发布自动化 → 其余维护项。前两项直接消除用户数据丢失与安全暴露。
- 版本号变更与 CHANGELOG 记录遵循项目既有规则：改动只升版本号记"未发布"段，发版前必须询问用户，不自动发版。
- 12 项改进来自 2026-09-05 的代码评审对话，实施时可按 ticket 拆分（/to-tickets）。
