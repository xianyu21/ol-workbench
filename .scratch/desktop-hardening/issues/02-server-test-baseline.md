# 02: 本地服务请求层测试基线

**What to build:** 为本地服务建立自动化测试套件（Node 内置 test runner，零新增依赖）。测试全部通过"发起真实 HTTP 请求 → 断言状态码/响应头/响应体"验证外部行为，不 mock 内部函数。用临时目录构造 AxHub 标准扁平导出夹具（中文文件名、编号前缀页面、框架页、resources 目录）。提供 `npm test` 入口。这是后续所有安全收紧工单的前置基线。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 覆盖目录穿越防护（`..`、编码变体被拒绝）
- [x] 覆盖页面扫描 API 响应结构（分组、过滤框架页、中文排序）
- [x] 覆盖工作台路由（首页 200、无尾斜杠 302、静态资源服务）
- [x] 覆盖缓存策略（资源类长缓存 immutable、HTML/JSON 短缓存）
- [x] 覆盖 Range 请求（正常 206、越界 416）与 HEAD
- [x] 覆盖 MIME 推断与中文路径解码
- [x] `npm test` 一条命令跑通全部用例

## Result

13 项请求层用例（真实 HTTP 请求断言）+ 9 项存储模块用例 = 22 测试全过。要点：目录穿越用例需原始 socket 发送请求行——Node/浏览器客户端会按 URL 规范预先规范化 `..` 点段（含 %2e%2e），服务端防御针对的是 curl/自定义客户端；`npm test` 使用 `node --test` 自动发现（`test/` 显式路径参数在本机中文+空格路径下不可用）。
