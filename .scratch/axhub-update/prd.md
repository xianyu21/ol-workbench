# PRD：AxHub 自动更新增强（axhub_auto_update_enhance）

> 文档类型：简单 PRD（产品目标 + 用户故事 + 需求池 P0/P1/P2 + 待确认问题）
> 模式：只读调研，不改源码

## 1. 项目信息

- **Language**：中文（与需求一致）
- **Programming Language / 技术栈**：Electron 33.4.11 主进程（Node.js，autoUpdater 封装在 `desktop/src/updater.js`，IPC 桥在 `desktop/src/ipc/update.js`）+ Vue 3.5 渲染进程（更新卡片 / 设置页）；`electron-updater ^6.8.9`；发布目标 NSIS（安装版，支持自动更新）+ portable（单文件，不支持自动更新）。
  - 说明：更新逻辑主要落在主进程与渲染进程 UI，沿用现有 Vue 渲染层；未引入 React/MUI。
- **Project Name**：`axhub_auto_update_enhance`
- **原始需求复述**：在现有 electron-updater 自动更新（启动 5s 后静默检查、后台下载、右下角进度卡、下载完提示重启、退出时自动安装）基础上增强三块：
  1. **更新渠道**：支持 stable / beta 等 channel，用户可在设置里切换；
  2. **静默安装健壮性**：后台下载完成后、安装/重启环节在「防病毒拦截、权限不足、文件被占用、磁盘空间不足」等异常下不得静默失败，要有明确反馈与兜底；
  3. **失败重试与回滚**：下载/安装失败可自动重试（带退避），安装后首次启动异常能回滚到上一可用版本。

## 2. 产品定义

### Product Goals

1. **渠道可控**：用户能按风险偏好在 stable / beta 间切换，始终清楚自己处在哪个渠道、能否拿到新版本。
2. **失败可见、可兜底**：更新链路（检查 → 下载 → 安装 → 重启）任何环节失败都不再静默吞掉，给出明确原因与可操作下一步。
3. **自愈与可恢复**：偶发失败自动重试（退避）自愈；灾难性失败（安装后启动异常）能安全回滚到上一版本，用户不丢可用环境。

### User Stories

- 作为内测用户，我想在设置里切到 beta 渠道，以便尽早体验新功能，稳定后切回 stable。
- 作为普通用户，我想在下载/安装失败时看到具体原因（如磁盘空间不足）和操作建议，而不是毫无反应地停留在旧版本。
- 作为网络不稳定用户，我想下载失败时应用自动重试几次，成功后我再重启安装，不必手动反复点。
- 作为遇到坏版本的受害者，我想新版本一启动就崩溃时能自动回滚到上一可用版本，或手动在设置里一键回滚。
- 作为谨慎用户，我想在「立即重启安装」前看到安装前置检查（空间/权限）通过，降低安装中途失败的概率。

## 3. 技术规范

### Requirements Pool

#### P0（必须）

**更新渠道**

- **P0-1** 设置页新增「更新渠道」选择器（stable / beta），选项持久化到配置；启动时 `autoUpdater.channel` 按配置生效，切换后立即触发一次 `checkForUpdates()` 并反馈结果。
  - 验收：切到 beta 后，后续检查只拉取 beta 渠道版本（验证请求 `latest-beta.yml`）；设置与关于页显示当前渠道；切换后 5s 内出现「检查中 / 有新版本 / 已是最新 / 检查失败」明确状态。
- **P0-2** 关于/设置页展示「当前版本 + 当前渠道 + 上次成功启动版本（lastKnownGood）」，让用户对账。
  - 验收：三项信息随实际状态实时显示，渠道与 `autoUpdater.channel` 一致。

**静默安装健壮性**

- **P0-3** 安装前置检查（preflight）：执行 `quitAndInstall` 前检查 (a) 系统盘剩余空间 ≥ 新版本所需（建议阈值 ≥ 300MB）；(b) 安装目录可写。任一不通过 → 弹出非模态错误卡，明确原因（如「磁盘空间不足，需释放 X MB」）+ 操作指引，**不进入安装**，不静默失败。
  - 验收：模拟磁盘空间不足 / 目录只读时，点击「立即重启安装」不触发安装，而是显示具体原因卡与「重试」「稍后处理」按钮。
- **P0-4** 安装/重启失败可见：将 `update:install` 与安装相关错误从「仅日志」改为向渲染进程发送明确失败事件（含原因分类），展示错误卡而非静默。
  - 验收：构造 `quitAndInstall` 抛错场景，渲染进程出现失败提示卡，而非无反应。
- **P0-5** 安装结果回检：重启后比对实际运行版本与「已下载待安装版本」标记；若不一致（说明安装未生效/被拦截），显示失败卡（归类：防病毒拦截 / 权限不足 / 文件被占用 / 磁盘空间不足 / 未知）+ 重试/手动安装入口。
  - 验收：标记待安装 vX 后人为让安装失败重启，应用仍运行旧版本且弹出失败卡与重试入口。

**失败重试与回滚**

- **P0-6** 下载失败自动重试（指数退避）：最多 3 次，间隔建议 30s → 2min → 5min；重试期间角落状态显示「重试中（第 n/3 次）」；耗尽后显示「更新失败」卡 + 手动「重试」按钮与原因。
  - 验收：断网触发下载失败后按退避自动重试；全部失败后展示手动重试入口；手动重试成功则继续流程。
- **P0-7** 记录 `lastKnownGoodVersion`：每次应用成功启动（UI 就绪）后持久化当前版本，作为回滚目标。
  - 验收：连续两次正常启动不同版本后，配置中 lastKnownGood 为最新一次成功版本。
- **P0-8** 首次启动异常自动回滚：安装后首次启动写入 `first-launch-pending` 标记（含 newVersion / oldVersion / oldInstallerPath）；若首次启动捕获未处理异常或启动超时（建议阈值 30s 未就绪），重启后自动运行上一版本安装包回滚，并提示「已回滚到 vX，原因：新版本首次启动异常」。
  - 验收：新版本首次启动故意抛错/超时 → 重启后自动回滚至旧版本并提示；旧版本可正常使用。
- **P0-9** 手动回滚入口：设置/关于页提供「回滚到上一可用版本 (vX)」按钮，二次确认后执行回滚（运行缓存的旧安装包）。
  - 验收：手动点击 → 二次确认弹窗 → 执行回滚 → 重启后运行旧版本。

#### P1（应有）

- **P1-1** 安装失败原因精细归类：尽量将 NSIS 退出码 / 可观测信号映射到「权限不足 / 文件被占用 / 磁盘空间不足 / 被防病毒拦截」，给出针对性指引（如「以管理员身份运行」「关闭占用程序/杀软」）。
- **P1-2** 检查（checkForUpdates）transient 错误也带退避重试（复用 P0-6 退避策略）。
- **P1-3** 安装多次失败后兜底：提供「下载完整安装包手动安装」或直接打开 Releases 页面的入口（复用便携版现有逻辑）。
- **P1-4** 更新前在本地缓存「上一版本安装包」(old installer) 到 userData 安全目录，保证离线可回滚；并对缓存体积设上限/清理策略。
- **P1-5** 重试/回滚操作在 UI 上有明确的进行中 / 成功 / 失败状态，避免用户重复点击。

#### P2（可选）

- **P2-1** 「跳过此版本」持久化：用户可跳过某版本，不再提示，直到更新版本出现。
- **P2-2** 更新历史页：展示历次更新版本、时间、成功/回滚记录。
- **P2-3** 企业/代理环境：支持自定义更新源 URL 与代理；渠道与静默策略可由管理员策略锁定。
- **P2-4** 弱网下的重试节流与「仅 Wi-Fi 下载」开关。

### UI Design Draft

- **设置页 / 关于**：新增「更新渠道」下拉（stable / beta）；显示「当前版本 / 渠道 / 上次成功版本」；保留「后台静默下载」开关与「检查更新」按钮；新增「回滚到上一可用版本」按钮（显示目标版本号）。
- **更新卡片（右下角非模态，沿用现有）**：
  - 进度卡：`下载中 X%`（新增重试态 `重试中（第 n/3 次）`）
  - 就绪卡：`发现新版本 vX · [立即重启安装] [稍后]`（点击安装前先做 preflight）
  - 失败卡（新增）：`更新失败：<原因分类>` + `[重试] [稍后处理/查看详情]`
  - 安装拦截卡（新增）：`无法安装：<磁盘空间不足/无写入权限…>` + 操作指引 + `[重试] [稍后处理]`
  - 回滚提示卡（新增）：`已回滚到 vX（新版本启动异常）` / `正在回滚…`

### Open Questions（待确认问题）

1. **beta 渠道发布链路**：GitHub Releases 目前是否已有 beta 预发布资源与对应 `latest-beta.yml`？electron-updater 的 channel 依赖按渠道生成 yaml，CI 发布流程由谁、何时产出 beta 包？
2. **回滚可行性 / 缓存策略**：NSIS 为覆盖式安装，回滚需「上一版本安装包」。是否允许更新前把当前版本 installer 缓存到 userData？安装包体积与本地占用是否可接受，还是改为保留上一版 resources 快照？
3. **首次启动异常的判定阈值**：自动回滚触发条件取「未处理异常」「启动超时（N 秒未就绪）」还是「渲染进程崩溃」？阈值多少能避免误回滚（如插件加载慢）？
4. **安装失败归因精度**：NSIS 退出码/信号有限，是否接受「尽力归类 + 通用指引」而非 100% 精确归因？
5. **静默下载失败的可感知程度**：重试期间是否仍保持角落静默状态，还是升级为可感知提示？企业代理网络下重试是否受限？
6. **适用范围**：上述增强是否仅针对 NSIS 安装版？portable（单文件）维持现有「去 Releases 页下载」指引、不纳入自动更新增强？
7. **渠道 × 静默默认组合**：切到 beta 后是否默认开启静默下载与自动安装？beta 用户是否应默认接受自动安装？
